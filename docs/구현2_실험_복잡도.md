# 구현2 샘플 실험 / 복잡도 정리

실행: `py .\experiment.py` (결과는 results 폴더에 저장)
아래 시간 숫자는 제 환경에서 돌린 값이라 컴퓨터마다 다를 수 있습니다. 크기를 늘렸을 때 몇 배가 되는지를 보면 됩니다.

## 1. 데이터

DTW는 모양이 같은데 속도나 타이밍이 다른 걸 맞춰주는 알고리즘이라서, 그런 차이가 있는 데이터 위주로 골랐습니다.
데이터마다 기준 / 같은 종류 / 다른 종류 3개씩 넣었고, 각 종류에서 앞에서부터 순서대로 가져왔습니다.
우리 코드는 숫자 한 줄만 입력받아서, 값이 여러 개인 데이터는 하나만 뽑아서 썼습니다.

### warp (직접 만든 사인파)
- warp_base (40개): 사인파 한 주기
- warp_slow (60개): 같은 모양인데 앞은 느리게, 뒤는 빠르게 늘림
- warp_shift (40개): 길이는 같고 옆으로 살짝 밀린 것

속도가 달라도 모양이 같으면 DTW 거리가 작게 나오는 걸 보여주려고 만들었습니다.

### vowel (음성)
- 원본: Japanese Vowels. 일본인 남자 9명이 모음 /ae/를 발음한 데이터
- 소리를 짧은 구간(25.6ms)으로 잘라서 구간마다 특징값 12개를 뽑은 것인데, 그중 첫 번째 값만 사용
- vowel_spk1_a (20개), vowel_spk1_b (26개): 1번 화자
- vowel_spk2_a (18개): 2번 화자

같은 사람이 같은 말을 해도 길이가 20, 26으로 다릅니다. 발표 자료의 "사과" 예시랑 같은 상황입니다.

### power (하루 전력 사용량)
- 원본: ItalyPowerDemand. 1997년 이탈리아 전력 수요를 하루 단위로 자른 데이터 (1시간 간격 24개)
- power_winter1, power_winter2: 겨울(10~3월) 하루
- power_summer1: 여름(4~9월) 하루

### motion (스마트워치 가속도)
- 원본: BasicMotions. 학생들이 스마트워치를 차고 걷기, 뛰기 등을 한 데이터 (10초, 100개)
- 센서 값 6개 중 가속도 x축만 사용
- motion_walking1, motion_walking2: 걷기
- motion_running1: 뛰기

다른 데이터랑 달리 정규화가 안 된 센서 값이라 뛰기는 거리가 엄청 크게 나옵니다. 다른 데이터랑 거리 숫자를 직접 비교하면 안 됩니다.

### gunpoint (손동작)
- 원본: GunPoint. 사람이 손을 움직일 때 오른손 위치(x좌표)를 영상에서 추적한 데이터 (150개)
- gunpoint_gun1, gunpoint_gun2: 허리에서 모형 총을 꺼내서 겨눴다가 다시 넣는 동작
- gunpoint_point1: 손가락으로 가리켰다가 내리는 동작

DTW 관련 논문에서 자주 쓰이는 데이터입니다.

## 2. 샘플 비교 결과 (results/pairs.csv)

시간축 고정은 DTW 없이 같은 시점끼리만 빼서 더한 값입니다 (길이가 같을 때만 계산 가능).

| 데이터 | 비교 | 길이 | DTW | 시간축 고정 | 경로 길이 |
|---|---|---|---|---|---|
| toy | sample1 vs sample2 | 5, 7 | 0 | - | 7 |
| toy | sample1 vs sample3 | 5, 7 | 13 | - | 7 |
| warp | base vs slow | 40, 60 | 1.44 | - | 60 |
| warp | base vs shift | 40, 40 | 3.67 | 15.24 | 44 |
| vowel | 같은 화자 | 20, 26 | 4.01 | - | 32 |
| vowel | 다른 화자 | 20, 18 | 9.17 | - | 24 |
| power | 겨울 vs 겨울 | 24, 24 | 5.85 | 7.60 | 30 |
| power | 겨울 vs 여름 | 24, 24 | 20.55 | 32.12 | 36 |
| motion | 걷기 vs 걷기 | 100, 100 | 80.2 | 149.0 | 132 |
| motion | 걷기 vs 뛰기 | 100, 100 | 1001.2 | 1110.3 | 135 |
| gunpoint | gun vs gun | 150, 150 | 5.34 | 20.72 | 196 |
| gunpoint | gun vs point | 150, 150 | 12.66 | 36.65 | 196 |

- 전부 같은 종류끼리 거리가 더 작게 나옴
- DTW는 시간축 고정보다 항상 작거나 같음. gunpoint 같은 종류는 20.7에서 5.3으로 많이 줄었는데, 동작 타이밍이 어긋난 걸 맞춰줘서 그런 것
- 길이가 다른 데이터(vowel, warp)도 그냥 비교됨
- 경로 길이는 항상 max(n, m) 이상, n+m-1 이하

한계: 샘플을 더 넣어서 비교해 보면 같은 종류/다른 종류 거리 범위가 겹치는 경우가 있었습니다.
- power: 겨울끼리 5.4 ~ 12.8, 겨울 vs 여름 5.9 ~ 20.6
- gunpoint: gun끼리 5.3 ~ 42.0, gun vs point 12.7 ~ 82.3

그래서 DTW 거리 하나만으로 항상 구분되는 건 아닙니다.

## 3. 실행시간 / 메모리 (results/timing.csv)

랜덤 시계열로 측정했고, 행렬 출력은 끄고(verbose=False) 3번 돌린 중앙값입니다.

n = m 일 때

| n = m | DTW (ms) | 백트레이싱 (ms) | 메모리 |
|---|---|---|---|
| 10 | 0.03 | 0.002 | 2.2 KB |
| 50 | 0.62 | 0.011 | 80 KB |
| 100 | 2.44 | 0.038 | 324 KB |
| 200 | 9.28 | 0.065 | 1.3 MB |
| 400 | 43.5 | 0.16 | 5.2 MB |
| 800 | 155.7 | 0.50 | 20 MB |
| 1600 | 588.4 | 1.21 | 81 MB |

- n이 2배가 되면 시간이랑 메모리가 대략 4배. log 그래프 기울기로 계산하면 약 1.99 (이론상 2)
- 백트레이싱은 n=1600에서도 1ms 정도라 전체 시간에서 거의 차지 안 함
- 메모리는 칸 하나에 약 33바이트 (파이썬 float이 리스트에 들어가면 이 정도 됨)

n = 200 고정, m만 늘렸을 때는 m이 2배가 되면 시간도 대략 2배 (기울기 약 1.1, 이론상 1)

## 4. 시간 / 공간 복잡도

n = 데이터1 길이, m = 데이터2 길이

시간
- 행렬 초기화, 거리 행렬, 누적 비용 행렬 모두 (n+1) x (m+1) 칸을 한 번씩 돌아서 각각 O(nm)
- 3번 돌지만 상수배라서 합쳐도 O(nm)
- 백트레이싱은 한 번 움직일 때마다 i나 j가 1씩 줄어들어서 최대 n+m-1번이면 끝남. O(n+m)
- 전체 O(nm), n = m 이면 O(n^2)

공간
- (n+1) x (m+1) 행렬을 저장해야 해서 O(nm)
- 백트레이싱하려면 행렬 전체가 있어야 해서 줄일 수 없음
- 거리값만 필요하면 바로 윗줄만 저장해도 돼서 O(min(n, m))까지 줄일 수 있음

더 빠르게 하는 방법 (참고)
- Sakoe-Chiba band: 대각선 근처 폭 w 안에서만 계산, O(nw)
- LB_Keogh: 계산 전에 하한값으로 확실히 먼 것들을 미리 걸러냄
- FastDTW: 근사로 O(n)
